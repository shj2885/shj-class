오늘의 원칙

코드는 클로드가 쓰고, 순서와 판단은 내가 한다 — 예쁜 사이트보다 문의가 들어오는 사이트.

코드는 읽지 않아도 됩니다. 대신 무엇을 어떤 순서로 시킬지, 결과가 맞는지는 내가 봅니다.

이것만은 꼭

  • 비밀번호·키는 Zoom 채팅, 단톡, 화면공유, 공개 저장소에 쓰지 않습니다. 관리자 비밀번호는 클로드가 만들어 Vercel 금고(환경변수)에만 넣어요.
  • 숫자·후기·경력은 AI가 채우지 않습니다. 모든 프롬프트에 "내가 준 내용만 쓰고 지어내지 마"가 들어 있어요.
  • 회사 일이면 회사 내부 자료·고객 개인정보는 넣지 않습니다. 오늘은 가짜 데이터로.

클로드가 일할 때

  • "이 작업을 허용할까요?" 창 — 오늘 만든 폴더 안의 일이면 허용. 모르는 창이면 손 들기.
  • 기다리는 시간은 정상입니다. 마음에 안 들면 처음부터 다시 쓰지 말고 "여기만 이렇게 바꿔 줘"로 이어서 말하세요.

프롬프트 1 · 우리 집 장보기 체크리스트 (첫 성공)

말로 시키면 클로드가 먼저 질문하고 → 계획을 보여 주고 → "시작해"라고 하면 만듭니다. 채울 칸이 없어요. 보기를 고르기만 하세요.

① 프롬프트 — 이대로 복사해서 쓰세요

우리 집 장보기 체크리스트를 하나 만들어 줘. 지금은 내 컴퓨터에서 나 혼자 쓸 거야.

어떻게 만들지는 나한테 질문으로 물어봐 줘.
질문은 5개, 한 번에 하나씩 물어보고, 질문마다 고를 수 있는 보기를 3~4개씩 같이 줘.
질문은 내가 보기를 눌러서 고를 수 있는 질문 카드(AskUserQuestion)로 띄워 줘.
질문 중에는 화면 디자인(색, 모양, 분위기 같은 것)을 고르는 질문도 꼭 넣어 줘.

질문이 끝나면 바로 만들지 말고, 내가 고른 것으로 계획서를 먼저 보여 줘.
(무엇을 만들지, 화면 구성, 디자인, 기능을 항목별로)
내가 "시작해"라고 하기 전에는 파일을 하나도 만들지 마.

항목마다 체크할 수 있게 하고, 새 항목도 추가할 수 있게 해 줘.
새로고침하거나 창을 닫았다 열어도 체크한 게 남아 있게, 이 브라우저 안에만 저장해 줘.
인터넷 서버나 데이터베이스는 쓰지 마.

다 만들면 바로 열어서 보여 줘.

② 이렇게 진행돼요 — 질문 5개에 보기 고르기 → 계획 확인 → 시작해 → 항목 체크하고 추가해 보기 → 새로고침해서 체크가 남는지 확인

지금 사이트가 어디에 있는지 확인합니다. 채울 칸이 없습니다.

지금 이 폴더에 어떤 파일이 있는지, 각각 무슨 역할인지 쉬운 말로 알려 줘.
그리고 방금 만든 페이지를 다른 사람이 내 폰이나 다른 컴퓨터에서 볼 수 있는지,
볼 수 없다면 왜 그런지 두 줄로 설명해 줘.

프롬프트 3 · 어디서나, 누구와도 같이 보려면?

방금 만든 장보기 체크리스트를 폰에서도, 가족과도 같이 보고 싶다면? 클로드에게 그대로 물어보세요. 채울 칸이 없습니다.

그럼 어디에서나 누구와도 함께 공유하고 핸드폰이나 PC에서도 똑같은 내용으로 확인하고 싶어. 어떻게 해야 하는지 중학생도 알아들을 수 있게 쉽게 설명해 줘.

프롬프트 4 · 회원가입 · 로그인까지 하려면?

오늘 배울 순서를 클로드에게 먼저 들어 봅니다. 지금은 설명만 듣고, 실제로는 프롬프트 8에서 한 번에 만들어요. 채울 칸이 없습니다.

배포하고 회원가입하고 로그인하는 기능도 넣고 싶어. 어떻게 해야 하는지 쉽게 설명해 줘.

프롬프트 4-2 · 첫 Commit

지금 상태를 Git으로 기록합니다. Commit = 그 시점 저장. 채울 칸이 없습니다.

이 폴더를 Git으로 기록을 시작하고, 지금 상태를 '장보기 체크리스트 처음 완성'이라는 이름으로 Commit 해 줘.
처음이라 필요한 설정이 있으면 무엇을 왜 하는지 한 줄씩 말해 주고 진행해 줘.

이름·이메일을 물으면 GitHub에 가입한 이메일을 쓰세요. 윈도우에서 Git이 없다고 나오면 사전 필수 세팅의 Git 설치 후 클로드 앱을 껐다 켜세요.

프롬프트 4-3 · Commit으로 되돌리기

일부러 바꿔 보고, Commit 해 둔 시점으로 되돌립니다. 두 상자를 차례로 넣으세요.

① 바꿔 보기

배경을 아주 진한 빨간색으로 바꿔 줘. (실험이라 Commit 하지는 마)

② 되돌리기

아까 Commit 한 '장보기 체크리스트 처음 완성' 상태로 되돌려 줘.
되돌린 뒤 지금 어느 Commit 상태인지 알려 줘.

프롬프트 4-4 · GitHub에 올려서 Commit 기록 보기

🐙 GitHub은 내 폴더의 '인터넷 보관함 + 기록 앨범'이에요

지금까지 한 Commit은 내 컴퓨터 안에만 있어요. 노트북이 고장 나면 기록도 같이 사라져요.

GitHub에 올리면(Push) 폴더와 Commit 기록이 통째로 인터넷에 보관돼요. 다른 컴퓨터에서도 열리고, 3교시에 Vercel이 여기서 파일을 가져가 내 주소를 만들어요.

실제 이름쉽게 말하면장보기 체크리스트로 보면
Git내 컴퓨터의 기록 카메라바꿀 때마다 사진을 찍어 둠
Commit사진 한 장 (이름 + 시간)'장보기 체크리스트 처음 완성'
GitHub사진을 모아 두는 인터넷 앨범github.com에서 누구나 열어 볼 수 있음
저장소 (Repository)앨범 한 권 = 프로젝트 하나my-site
Push내 컴퓨터 사진을 앨범에 올리기올릴 때마다 Commit 수가 늘어남

① 올리기 — 채울 칸 없음

이 폴더를 내 GitHub에 올려 줘. 저장소 이름은 my-site로 하고 공개(Public)로 해 줘.
올리는 데 필요한 설치·설정·저장소 만들기는 전부 네가 해 줘.
내가 꼭 직접 해야 하는 건 GitHub 로그인뿐이니까,
로그인 창이 뜨면 그때만 무엇을 누르면 되는지 한 줄로 알려 주고, 나머지는 끝까지 진행해 줘.

다 올리면 이 세 가지를 알려 줘.
1. 브라우저에서 열 수 있는 내 저장소 주소
2. 지금까지 Commit이 몇 개인지, 각각 무엇을 바꾼 건지 표로
3. GitHub 화면에서 Commit 기록을 보는 곳(눌러야 할 버튼 이름)

② 한 번 더 — Commit 수가 늘어나는 것 보기

체크리스트에 '두부' 항목을 하나 추가하고 Commit 한 다음 GitHub에 올려 줘. Commit 이름은 네가 정해 줘.

프롬프트 5 · 마법의 프롬프트

Commit을 까먹어도 괜찮게, 클로드가 알아서 기록(Commit)하고 GitHub에 올리도록 규칙을 한 번 정해 둡니다. 어느 폴더에서 일하든 계속 지켜져요. 채울 칸이 없습니다.

내가 Commit 하라고 말하는 걸 자주 까먹을 것 같아.

앞으로는 기능 하나를 다 만들었거나 큰 수정이 끝날 때마다
내가 말하지 않아도 네가 알아서 해 줘.
1. 내 PC에 Commit 해 줘. Commit 이름은 무엇을 바꿨는지 알 수 있게 네가 정해 줘.
2. 그다음 GitHub에도 올려(Push) 줘.

글자 하나 고치는 정도의 작은 수정은 모아서 한 번에 해도 돼.
끝나면 "Commit 했어요: (이름)"이라고 한 줄로 알려 줘.
Git 기록을 아직 시작하지 않은 폴더라면, 시작해도 되는지 먼저 물어봐 줘.

이 규칙은 어느 폴더에서 일하든 계속 지켜지게
내 전역 규칙 파일(~/.claude/CLAUDE.md)에 적어 두고, 적은 내용을 보여 줘.
파일이 없으면 새로 만들고, 이미 있으면 기존 내용은 그대로 두고 아래에 붙여 줘.

당황해서 "다 지우고 다시 해 줘"는 하지 마세요. 설명부터 받는 게 제일 빠릅니다. 그래도 막히면 새싹이 조교 · 단톡 도우미 채널로.

Supabase 연결 (Vercel 화면에서, 3분)

Claude in Chrome이 연결돼 있으면 클로드가 알아서 연결해요. 없을 때만, 클로드가 "Supabase를 연결해 주세요"라고 하면 아래 순서대로 직접 누르세요.

vercel.com → 내 프로젝트 → 위쪽 Storage → 오른쪽 위 Create Database → Supabase → 약관 동의 → 지역 Seoul · Free Plan → Continue → 이름 my-site-db → Create → 프로젝트 연결 화면에서 Connect → 클로드에게 "연결했어, 계속해 줘"

두 가지 조심

  • 목록에 다른 데이터베이스가 보여도 그 Connect가 아니라 Create Database. 다른 장부와 섞여요.
  • 프로젝트 연결 화면의 Custom Prefix는 비워 두기. 글자를 넣으면 키 이름이 바뀌어 코드가 못 찾아요. Sensitive는 켜 둔 그대로.

프롬프트 14 · 회원가입 · 로그인 (Supabase Auth)

Supabase Auth로 이메일 회원가입·로그인을 만들어 줘.
- 로그인한 사람만 /members 페이지를 볼 수 있게.
- 비밀번호 재설정 메일도 되게.
- 회원가입 화면에 개인정보 수집·이용 동의(필수)와 처리방침 링크 자리를 넣어 줘. 처리방침 내용은 지어내지 말고 자리만.
- 키는 환경변수로만, 브라우저 쪽에는 공개용 키만 쓰고 그 이유를 한 줄로 설명해 줘.
만들기 전에 내가 Supabase 화면에서 켜야 할 설정을 먼저 알려 줘.

회원 정보를 받으면 개인정보 처리방침이 필요합니다. 구글·카카오 로그인은 각 회사 개발자 설정이 따로 필요해요.

프롬프트 15 · 블로그를 붙일 때 (RSS + sitemap)

🗺️ sitemap은 우리 집 지도, RSS는 새 소식 알림. 소개 + 문의 사이트는 sitemap이면 충분하고, 블로그·소식처럼 글이 자주 올라오면 RSS도 추가하세요. 네이버 서치어드바이저에 RSS 제출 칸이 있어요.

내 사이트에 블로그 글을 올릴 거야.
새 글이 생기면 자동으로 RSS(rss.xml)에도 추가되게 해 주고,
sitemap.xml에도 같이 들어가게 해 줘.
