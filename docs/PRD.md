# 사이트 설계도(PRD) — 혜정쌤의 코딩도깨비

부제: 내 손으로 뚝딱! 상상력은 쑥쑥!

작성일: 2026-10-25 · 이 문서는 사이트를 고칠 때마다 다시 보는 기준이다.

## 1. 한 줄 정의
수업에 필요한 사이트들을 한곳에 모아 두고, 수강생이 누르면 바로 들어갈 수 있게 하는 링크 모음 사이트.

## 2. 손님
- 누가: 내 수업 수강생
- 어디서 알고 오나: 수업 중에 주소를 보고 직접 입력해서 들어온다

## 3. 손님이 궁금한 것 (들어오자마자)
1. 오늘 수업에서 쓸 사이트는 어디인가
2. AI 도구 · 디자인·이미지 도구 · 수업 자료·과제 · 협업·저장 도구 중 필요한 사이트는 어디 있나
3. (미정)

## 4. 믿게 할 증거 (실제로 있는 것만)
- (미정) — 수강생용 링크 모음이라 이번에는 해당 없음
- 후기: (실제 후기가 생기면 넣는다. 지금은 자리만)

## 5. 누르게 할 버튼 하나
- 버튼 이름: 맨 위 '오늘 쓸 사이트' 카드
- 누르면: 그 사이트가 새 탭에서 열린다 (수업 사이트 화면은 그대로 남는다)

## 6. 페이지 구성 (위에서 아래로)
**첫 화면 (`/`)**
1. 사이트 이름 + 한 문장
2. 오늘 쓸 사이트 — 몇 개만 크게
3. AI 도구
4. 디자인·이미지 도구
5. 수업 자료·과제
6. 협업·저장 도구

**관리자 화면 (`/admin`, 비밀번호로 잠김)**
- 링크 더하기 · 고치기 · 빼기 (이름, 주소, 묶음)
- '오늘 쓸 사이트'로 올리기 / 내리기

## 7. 문의 폼에서 받을 것
- 이번에는 문의 폼 없음 (9번 참고)

## 8. 정확해야 하는 사실 (사용자가 말한 그대로)
- 사이트 목록(이름·주소): 만들 때 사용자가 준다. 클로드가 지어내지 않는다
- 묶음 네 개: AI 도구 · 디자인·이미지 도구 · 수업 자료·과제 · 협업·저장 도구
- 들어오는 방법: 주소 직접 입력 → 주소는 짧고 치기 쉬워야 한다 (주소: 미정)
- 가격 · 시간 · 위치 · 연락 방법: 해당 없음

## 9. 이번에 넣지 않을 것
- 문의 폼 (다음에 필요하면 더한다)
- 수강생 회원가입·로그인
- 결제
- 검색창 (링크가 많아지면 다음에)
- QR코드·단톡방 공유용 화면

## 10. 첫 화면 한 문장 후보
1. 오늘 수업에 쓸 사이트, 여기서 바로 들어가세요.
2. 수업에 필요한 사이트를 한곳에 모았어요.
3. 누르면 바로 열려요. 오늘 쓸 사이트부터 시작하세요.

## 11. 다음에 할 것
- 실제 사이트 목록 받기 (만들 때)
- ~~사이트 이름 정하기~~ → 코딩도깨비 (2026-10-25)
- 짧은 주소(도메인) 정하기
- 링크가 많아지면 검색창 더하기

## 12. 만드는 방법 (클로드가 끝까지 만들 때 기준)
- 분위기: 발랄한 · 참고 디자인: 없음 — 클로드가 정함
- 링크 저장: 예 → Supabase에 `links` 표(이름 · 주소 · 묶음 · 오늘 쓸 사이트 여부 · 순서) + `/admin`에서 직접 관리
  - leaderpl-admin 스킬은 문의함 기준이라, 같은 원칙(서버 키는 `/api`에만, 표는 RLS 켜기, 비밀번호는 `ADMIN_PASSWORD` 환경변수)을 링크 표에 맞춰 쓴다
  - 첫 화면은 `/api`에서 링크 목록을 읽어 보여 준다 (읽기만, 키는 브라우저에 없음)
- 회원가입: 이번엔 아니요
- 배포: GitHub 공개 저장소 + Vercel

## 13. 만드는 순서 (클로드가 처음부터 끝까지 한 번에)
1. 스타일(색·글꼴)을 '발랄한' 분위기에 맞게 정하고 첫 화면부터 만든다 (휴대폰 화면 우선)
2. GitHub 공개 저장소에 올리고 Vercel로 배포해 내 주소를 만든다
3. `links` 표 → 첫 화면에 목록 보여 주기 → `/admin`에서 링크 더하기·고치기·빼기·'오늘 쓸 사이트' 지정까지 만든다
4. 사용자가 준 사이트 목록을 넣는다
5. 다 만든 뒤 한 번에 보고: 내 사이트 주소 · 관리자 주소 · 확인 방법 · 사용자가 할 일
- 사용자가 직접 할 일(이때만 멈춤): 로그인, 결제, 관리자 비밀번호(ADMIN_PASSWORD) 입력
